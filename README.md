# City Liveability

**나에게 가장 잘 맞는 도시는 어디일까?**

고등학교 지리·사회 수업에서 개인의 생활 가치관과 도시의 차이를 탐구하는 한국어 웹앱입니다. React, TypeScript, Vite, Tailwind CSS, Recharts로 만든 브라우저 전용 MVP입니다.

## 구현 범위

- 핑크·아이보리·세이지 톤의 반응형 시작 화면: 특정 도시나 국기를 미리 보여주지 않습니다.
- 나이, 희망 직업, 예상 연봉(만원/년), 대륙, 선택 별명 입력
- 경제성·안전성·자연환경·교통·문화·인프라 6개 영역의 20문항
- 5점 척도, 진행률, 이전 질문, 문항 바로 이동, 답변 수정
- 6개 대륙 34개 도시에서 1순위 + 차순위 2개 추천
- 개인 중요도와 도시 조건의 레이더 그래프, 가중치와 추천 기여도 설명
- PNG 결과 카드 저장, 지원 기기의 기본 공유, 지원하지 않는 기기의 문구 복사
- 지리적 차이와 생활 기회에 관한 성찰 질문
- 실제 학생 정보 없이 고정된 가상 응답 60명으로 계산한 교사용 추천 빈도 데모
- 다시 검사하기, 입력 초기화, 사진 오류 시 대체 표시

**중요:** 도시 점수와 생활비는 모두 교육용 가상 예시입니다. 검증된 외부 통계는 현재 포함하지 않습니다. 위치·기후·교통 설명은 학습용 일반 요약으로, 최신 현지 정보 확인이 필요합니다. 이 앱은 실제 취업·비자·의료 이용 자격이나 이주 적합성을 판단하지 않습니다.

## 설치와 실행

Node.js 22 이상과 npm을 설치하세요. 이 클라우드에서는 Node.js 24로 확인했습니다.

```bash
cd /workspace/City-Liveability
npm ci --cache /workspace/.npm-cache
npm run dev
```

개인 PC에서는 저장소를 내려받은 폴더에서 `npm ci`와 `npm run dev`를 실행하면 됩니다. 터미널에 표시되는 개발 서버 주소를 브라우저에서 여세요. 클라우드 온보딩 화면은 localhost 웹 미리보기 링크를 지원하지 않으므로 내부 요청과 브라우저 자동 테스트로 검증했습니다.

```bash
npm run typecheck
npm test
npm run build
npm run preview
```

`npm run preview`는 빌드된 `dist/`를 확인하는 명령입니다. 실제 서비스 운영에는 Vercel 같은 정적 호스팅을 사용하세요. 서버·DB·API 키는 필요 없습니다. 한글 웹폰트는 npm 의존성으로 앱에 포함되며 별도의 Google Fonts 요청을 하지 않습니다.

## 추천 알고리즘

1. 모든 20문항에 응답해야 합니다. 영역별 문항 수가 달라도 평균을 사용해 문항 수가 많은 영역에 유리하지 않도록 했습니다.
2. 개인 중요도 `p` = 해당 영역의 응답 평균 ÷ 5 × 100. 따라서 범위는 20~100입니다. 높은 중요도는 그 조건을 더 중시한다는 뜻이며, 낮은 중요도가 좋은 안전이나 인프라를 싫어한다는 뜻은 아닙니다.
3. 원시 가중치 = `0.03 + 0.97 × (p / 100)^3`. 여섯 가중치 합이 1이 되도록 정규화합니다. 세제곱은 중요하게 선택한 영역의 차이를 강조하는 교육용 모델 선택이며 통계적으로 검증한 계수가 아닙니다.
4. 연봉은 입력 만원 × 10,000으로 원화 환산합니다. 예시 비용 여유 = `min(100, 연봉 × 0.7 / 연간 예시 비용 × 100)`. 70%는 세금 추정치가 아닌 가상 지출 가능 비율입니다.
5. 도시 경제성 = 원래 경제성 점수 × 0.75 + 예시 비용 여유 × 0.25. 나머지 다섯 점수는 연봉으로 바꾸지 않습니다.
6. 최종 적합도 = 여섯 도시 점수 × 정규화 가중치의 합. 선택한 대륙 안에서 내림차순 정렬합니다. 동점에는 고정 도시 ID를 사용합니다. 무작위 추천이나 빈도 조정은 없습니다.
7. 추천 이유는 각 영역의 최종 점수 기여도를 기준으로 설명합니다. 개인 중요도·도시 조건·가중치·기여도를 결과에서 확인할 수 있습니다.

계수는 `src/lib/recommend.ts`의 `algorithmConfig`에서 바꿉니다. 공식 변경 시 결과의 설명 문구와 테스트도 함께 갱신하세요. 나이·희망 직업은 생활을 상상하는 교육적 입력이며 순위 계산에 사용하지 않습니다.

초기 선형 가중치에서는 균형 잡힌 도시 하나가 약 99%로 편중되었습니다. 수정한 공식은 고정 연봉 4,000만원·전체 대륙·영역별 1~5점의 모든 15,625가지 조합에서 26개 도시가 1순위에 등장했고, 최대 비율은 약 43.9%였습니다. 이는 가상 모델의 제한된 민감도 점검이며 실제 사용자 분포나 공정성의 증명이 아닙니다. 모든 도시가 1순위가 되도록 인위적으로 보정하지 않았습니다.

## 도시 데이터 수정

`src/data/cities.json`의 각 객체를 수정하세요. `id`는 중복되지 않는 영문 고정값이며, `continent`는 화면의 대륙 표기와 같아야 합니다.

- `name`, `english`, `country`, `continent`, `lat`, `lng`: 이름과 위치
- `climate`, `transport`, `housing`, `advantages`, `disadvantages`: 특징과 장단점
- `scores`: **경제성, 안전성, 자연환경, 교통, 문화, 생활 인프라** 순서의 0~100 예시 점수
- `cost`: **주거비를 포함한 원화 연간 가상 총 생활비**, 원 단위
- `costMetadata`: 단위, 시나리오 기준 연도(2026), 예시 여부, 근거
- `ratingMetadata`: 영역별 예시 여부, 기준 연도, 평가 설명
- `statistics`: 현재 빈 배열. 검증 가능한 실제 통계를 추가할 때 지표명·수치·단위·연도·원문 URL을 넣는 별도 공간
- `images`: 3개 이미지 경로 또는 URL
- `imageSource`: 사진 출처와 실제 해당 도시 사진인지 여부

**실제 통계와 예시 점수를 섞지 마세요.** 현재 예시 모델에는 비교 가능한 현지 물가, 환율, 소득·세금 자료가 없습니다. 검증된 지표로 교체하려면 기준 연도와 단위를 통일하고 평가 방법을 새로 설명해야 합니다. 자료가 부족한 점수에 임의로 0을 넣지 말고, 계산 제외 및 가중치 재정규화를 구현하거나 지금처럼 한계를 명시하세요. 신규 도시는 반드시 6개 영역과 메타데이터를 함께 입력하고 테스트하세요.

### 이미지의 현재 한계

각 도시에 3개 이미지 슬롯과 Unsplash 출처를 연결했습니다. **현재 이미지는 공통 도시·자연 분위기 이미지로, 해당 도시의 실제 대표 사진이 아닙니다.** 결과 화면과 대체 이미지 설명에도 이를 명시했습니다. 실제 도시별 3장씩의 사진은 출처·촬영 위치·사용 허가를 확인한 뒤 교체해야 합니다.

현재 클라우드의 외부 이미지 요청은 네트워크 정책에서 차단되었습니다. 따라서 원격 사진 정상 로드는 검증하지 못했고, 오류 시 대체 화면과 결과 작동을 검증했습니다. 이미지 접근용 `images.unsplash.com` 요구사항은 환경 구성 초안에 저장합니다. 환경 설정에서 검토·저장해 적용한 후 해당 요청을 다시 확인해야 합니다. 서비스 배포 뒤에도 원격 URL의 변동 가능성이 있으므로 허가된 사진을 `public/cities/`에 보관하는 방식을 권장합니다. 외부 이미지에는 `referrerPolicy="no-referrer"`를 사용하며 학생 입력을 URL에 포함하지 않습니다.

## 테스트

```bash
npm test                 # Vitest: 주요 알고리즘 단위 테스트
npm run typecheck        # TypeScript 검사
npm run build            # 프로덕션 빌드
npm run test:e2e          # PC·태블릿·모바일 브라우저의 실제 흐름
```

이 클라우드에서는 설치된 `/usr/bin/chromium`을 사용합니다. 다른 컴퓨터에서는 다음을 먼저 실행하세요.

```bash
npx playwright install chromium
npm run test:e2e
```

다른 Chromium 경로는 `CHROMIUM_PATH` 환경변수로 지정할 수 있습니다. E2E는 시작 화면 → 입력 → 20문항 → 유럽 대륙 추천 → PNG 저장 → 답변 수정 → 동일 결과 → 초기화를 확인합니다. 이전 문항·기본 정보 유지와 교사용 데모도 확인합니다. 이미지 요청은 의도적으로 실패시켜 대체 표시를 검증합니다. 이는 원격 사진이 정상 로드된다는 검증이 아닙니다. 결과 파일과 화면 캡처는 `test-results/`에 생성됩니다.

## 개인정보와 확장

입력값은 React 메모리 상태에서만 처리합니다. `localStorage`, 쿠키, 서버 저장, 설문 API, 학생 분석 도구가 없습니다. 새로고침하면 입력이 사라집니다. 사용자가 공유 버튼을 누르면 기기의 공유 기능으로 결과 문구를 넘기며, PNG 저장은 로컬 다운로드입니다.

교사용 화면은 가상 응답만 계산합니다. 실제 학생 응답 수집, 학급별 집계, 관리자 인증, CSV/엑셀 다운로드, DB는 아직 구현하지 않았습니다. 후속 단계에서 인증·권한·학급 분리·동의·삭제 정책·보관 기간을 먼저 설계해야 합니다. 데이터 저장을 추가할 때 현재의 메모리 상태와 별도의 저장 서비스 인터페이스를 분리하세요.

## Vercel 배포

1. 위 방법으로 GitHub에 코드를 반영합니다.
2. Vercel에 로그인하고 **Add New → Project**에서 저장소를 가져옵니다.
3. 프레임워크는 **Vite**, Install Command는 `npm ci`, Build Command는 `npm run build`, Output Directory는 `dist`로 설정합니다.
4. Node.js 22 이상을 선택하고 Deploy를 실행합니다. 환경변수나 API 키는 필요 없습니다.
5. 배포된 주소에서 설문 전체 흐름, 모바일 화면, 사진 로딩, 다운로드·공유를 확인하세요. 공유 기능과 클립보드는 HTTPS 또는 localhost 등 지원 환경이 필요합니다.

현재 URL 경로 기반 라우팅을 쓰지 않아 별도 SPA rewrite 설정은 필요 없습니다. 실제 Vercel 배포는 이번 작업에서 실행하지 않았습니다.
